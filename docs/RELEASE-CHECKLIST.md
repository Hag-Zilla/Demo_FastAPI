# Release Checklist

<!-- cspell:words oneline -->

Use this checklist for each release of MyBro.

## Pre-Release (1-2 days before)

- [ ] Update `CHANGELOG.md`: move all `[Unreleased]` sections to a new versioned section `[X.Y.Z] - YYYY-MM-DD`
- [ ] Run all tests locally:

  ```bash
  uv sync --group dev
  uv run pre-commit run --all-files
  python3 tests/test_validate_instructions.py
  bash tests/test_scripts.sh
  ```

- [ ] Review all changes since last release: `git log --oneline <last-tag>..HEAD`
- [ ] Verify no secrets, credentials, or sensitive data in the diff
- [ ] Update `docs/STANDARDS.md` "Last updated" date to today
- [ ] Commit changes: `git commit -m "chore: prepare release X.Y.Z"`
- [ ] Open a PR, request review, merge when green

## Release Day

### Create the release tag

```bash
# Ensure main is up to date
git checkout main
git pull origin main

# Create an annotated tag
git tag -a vX.Y.Z -m "Release X.Y.Z: <one line summary from CHANGELOG>"

# Push the tag (this triggers CI workflows)
git push origin vX.Y.Z
```

### Generate release artifacts

- [ ] Wait for CI to complete (GitHub Actions workflow)
- [ ] Download or verify artifacts from the release workflow:
  - `bootstrap-copilot.sh`
  - `check-updates.sh`
  - `CHECKSUMS` (auto-generated by CI)
- [ ] If using GPG signing (optional):

  ```bash
  gpg --detach-sign --armor bootstrap-copilot.sh
  gpg --detach-sign --armor check-updates.sh
  ```

### Create GitHub Release

1. Go to [Releases](https://github.com/Hag-Zilla/MyBro/releases)
2. Click "Create a new release"
3. Set tag version: `vX.Y.Z`
4. Set title: `Release X.Y.Z`
5. Copy the relevant section from `CHANGELOG.md` as the description
6. **Attach assets**:
   - `bootstrap-copilot.sh`
   - `check-updates.sh`
   - `CHECKSUMS` (if generated)
   - `.asc` files (if GPG-signed)
7. Check "Set as the latest release"
8. Click "Publish release"

### Post-Release

- [ ] Verify `bootstrap-copilot.sh` can resolve the new release tag:

  ```bash
  curl -sSfL "https://api.github.com/repos/Hag-Zilla/MyBro/releases/latest" \
    | grep '"tag_name"' | cut -d'"' -f4
  # Should output: vX.Y.Z
  ```

- [ ] Test bootstrap in a fresh repo:

  ```bash
  mkdir /tmp/test-repo
  cd /tmp/test-repo
  git init
  bash <(curl -sSfL https://raw.githubusercontent.com/Hag-Zilla/MyBro/main/scripts/bootstrap-copilot.sh)
  ls -la .github/copilot-instructions.md
  ```

- [ ] Document any breaking changes in a GitHub discussion or the README
- [ ] Update the README badge if it references version numbers
- [ ] Announce the release (e.g., GitHub Discussions, internal channels)

## Rollback (if needed)

If a release has critical issues:

1. Delete the tag: `git tag -d vX.Y.Z && git push origin --delete vX.Y.Z`
2. Create a patch release `vX.Y.Z+1` with the fix
3. Document the issue in the CHANGELOG under the new release
